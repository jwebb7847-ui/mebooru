## Concrete remaining c engineering gates (ordered)

1. **Make eligibility explicit before any landing.** `new_receipt.go:newOnlyRowsMode` restricts .png, unique SHA/URL, explicit provenance and no parent; `composed_receipt.go` expects one file/row; held context requires .png and empty job; restored requires empty job; `client_extras.go:validClientJob` refuses custom via, commentary and source. `naming.go:applyNamingModeLocked` refuses EqualFold(old,final); existing destination directory required. Do not infer unsupported claims as empty or strip them. Build an owner-side exact pre-mutation eligibility/plan contract; then prove legacy parity for every supported strict extension/claim combination and exact no-op naming, including case-sensitive/case-insensitive filesystem behavior, destination creation/collision, preserved manual metadata and existing duplicate/restore relationships. Unsupported cases must refuse before publication, not after partial gallery changes. No automatic legacy fallback that bypasses strict policy. Replacement, normal/deep/archive catch-up have separate existing migration obligations; do not expand strict scope without design.
2. **Multi-item and partial outcomes.** Seal and initial publication can handle multiple verified files; common witness carries one Row/PathID/FileIdentity, and cleanup assumes single-file evidence. Partial placement fixture proves refusal/no blind replay, not complete batch behavior. Define exact per-item disposition and durable operation aggregate with identity and approved subset, including duplicates across posts, mixed held/new/restored, blocked/changed items, cancellation and lost replies at every mutation/receipt boundary. Reuse verified single-item semantics where feasible, preserve source order/relationships, never equate transfer success or absent DB row with final outcome. Test synthetic mixed windows and 200-post actual strict-runtime integration; do not use legacy 200-post probe as proof of managed batch commit.
3. **Resource and destination boundaries.** `allocator.go:scope` rejects different volume; `spaceFor` is preflight, 3*payload + per-entry metadata overhead, explicitly not a live disk quota. Approved model includes verified copy fallback when safe same-filesystem move unavailable. Prefer destination-local private staging outside scan trees, independently verify actual device and filesystem capabilities; where unavailable, design bounded verified copy to an exclusive destination-local prepared object and no-clobber publication, no overwrite or arbitrary path. Enforce owner byte/file limits while writing (include media, sidecars, temp/partial files and all concurrent leases); monitor/cancel and confirm writer cleanup on limit breach, deny further writes, retain uncertain evidence. A periodic check alone is not a hard byte quota; state platform enforcement limitations, test unknown/unavailable space, exhaustion during writing, volume disappearance, link unsupported and cross-volume collision/recovery. No new trust or portability claim without evidence.
4. **History and explicit recovery.** `allocator.go:Allocate` refuses at len(records)>=1024 even if all closed; `inventoryWithClosure` reopens every historical record and calls `closedCharge`, which reads seal/publication, retained native sidecar, manifest and policy and recomputes digest. `spaceFor` charges full per-entry worst-case metadata even for closed records. This is fail-closed, but a permanent workload ceiling and O(history) repeated validation cost; a normal long-lived watch cannot rely on it. Preserve exact replay refusal and full provenance; design bounded active index plus historical receipt/identity lookup and crash-consistent archival/compaction that retains evidence. Benchmark >1024 completed operations and mixed active history, restart, duplicate key, corruption, missing index and interruption. Do not simply raise the cap, discard evidence, trust unchecked cache, or delete records. Any change to retention/privacy policy needs owner approval; preserving evidence and reorganizing it does not. Abandon only on independently proven no-live/no-future writer and no uncertain commit, exact rooted inventory, durable intent/result and explicit recovery. Unknown outcome remains retained/blocked; distinguish inspectable state from authorized deletion. Test abandoned empty/precommit, revoked, partial, lost acknowledgement and never-regrant operation ID.
5. **Production owner integration boundary.** Allocator package says not mounted by production; mutex is local only; scope, SealObserver and separate cleanup/closure callbacks are trusted inputs; terminal witness is not a grant. WatcherRunning checks do not provide exclusive scanner/writer fence. Before any production route is enabled, tie stable gallery/job/operation identity, persisted custody/no-live/no-future writer proof, current policy/generation, owner-only scanner/edit exclusion and exact durable receipt/outcome to actual local library orchestrator. Define/test private adapter and fail-closed loss/revocation across phases; actual queue/watch/PTR/runtime network admission/drain and scheduler remain d, integrated disposable profile e, final acceptance II.6.5. No direct worker DB write, no arbitrary worker path, no production fallback, no deletion of existing user state. Keep old routes as currently authorized until full acceptance.
