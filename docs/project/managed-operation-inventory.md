## Authority model

- Library -> worker: authorize explicit requested action and existing user permissions; scope to library-selected gallery and stable job/item where relevant. Offline submission is held work, never an execution grant. Reauthorize at execution, not only enqueue. Use persisted online consent and an active drain lease for actual WAN; cancel/cleanup before offline acknowledgement.
- Worker -> library: explicit library-owned operation/gallery/job/image grants, not worker-supplied self-authorization or active-gallery defaults. Catalog discovery has an explicit separate permission; do not infer write or image access from it. Keep gallery lifetime lock and validate identity under it. Do not equate a gallery display name with a durable identity across rename/delete/recreation; resolve lifecycle before granting persistent job capability.
- Worker -> custodian: separate role pair. Accept typed operation-specific plans, not executable paths, raw args, environment, arbitrary URL fetch, filter expressions or paths. Approved runtime/config/staging must be trusted local state; authorize online separately from job permission. Keep output/exit/cleanup proof distinct. Unknown or unsupported plans fail closed, not legacy fallback.
- Local/mixed/online below classify target execution, not current enforcement. Existing HTTP verb/scopes, protocol registry and queue hold flags are not sufficient authorization. Preserve current external plugin approval independently. No new credential reveal or arbitrary configuration bridge.
